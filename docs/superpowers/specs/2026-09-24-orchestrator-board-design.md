# Orchestrator board — design (2026-09-24)

## Purpose

One generated page that shows everything in flight for a repository: what is waiting on the
user, what the orchestrator is doing now, which agents (subagents inside a session and separate
desktop sessions) are working on which slice with what model, the merge lane of open PRs with
CI state, and the beads backlog. Rendered from data the toolkit already produces; no extra
sessions, no polling, no ongoing token cost. Viewed in the desktop app's browser pane (as a
local file or a local server) and optionally published as a private Artifact for the phone.

Modelled on Alan's ExoCortex board (waiting-on-human / now / in-flight / merge lane / tasks),
but generated by a script on a hook instead of by a status session.

## Data sources (all local, all read-only)

| Section | Source | How |
|---|---|---|
| Waiting on you | `.claude/board/waiting.md` (orchestrator appends per the progress contract); beads issues labelled `needs-input`; PRs whose checks failed; sessions whose last assistant turn is an unanswered `AskUserQuestion` | merged, deduplicated, newest first |
| Now | the most recently active session's last assistant text (≤300 chars); the beads epic in progress | transcript scan; `bd list --json` |
| In flight | beads issues `in_progress` and `open` under active epics, with assignee, labels (`model:*`, `tries:*`, `slice:*` conventions), blockers | `bd list --json` (falls back to `bd list` text) |
| Agents | sessions for this repo and its worktrees (`~/.claude/projects/<repo>*/*.jsonl`): title, model, effort, branch, last activity, tokens, state (running if modified in the last 5 min and no trailing Stop); subagents from each session's `subagents/*.jsonl`: name, model, tool uses, running/done | transcript scan (bounded read of the tail) |
| Merge lane | open PRs with head branch, draft flag, check rollup, updated time | `gh pr list --json` |
| Backlog | counts by status and the last 5 closed | `bd list --json` |

Nothing is written to beads, git, or GitHub.

## Components

### `scripts/board.py` (stdlib only)

- `build` — collects the sources above (each in a try/except; a failed source renders as a
  greyed "unavailable: <reason>" panel, never aborts), renders `.claude/board/index.html`
  and `.claude/board/board.json` atomically. Options: `--repo <path>` (default cwd), `--out`,
  `--quiet`, `--since-minutes` (session activity window, default 5), `--no-gh`.
- `open` — prints the `file://` URL and, on macOS, opens it (`open`); `--serve [port]` runs
  `http.server` bound to 127.0.0.1 for the browser pane.
- Rendering: one self-contained HTML page, no external assets, light/dark via
  `prefers-color-scheme`, header with repo, branch, HEAD short SHA, built time; six sections
  in the order above; badges for state; relative times; sensitive text (secrets patterns from
  `secret_scan.py`) is never rendered.
- Runtime budget: under 2 s for a repo with 30 sessions; transcripts are read from the tail
  (last 512 KB) to find the latest assistant message and usage.

### `hooks/board_refresh.py` + `hooks/hooks.json`

- Registered on `Stop` and `SubagentStop`. Solo-safe: exits 0 immediately unless
  `.claude/board/` exists in the repo or `CLAUDE_BOARD=on`. Runs `board.py build --quiet`
  with a 15 s timeout; fail open; never prints to stdout (no context cost).

### `skills/board/SKILL.md` (user-invoked, `argument-hint: "[open|serve|publish]"`)

- `/board` builds and opens the page in the browser pane; `/board serve` starts the local
  server and opens it; `/board publish` builds and publishes the page as a private Artifact
  (via the Artifact tool) and returns the link. First run creates `.claude/board/` (enabling
  the hook) and adds it to `.gitignore`.

### Progress-contract tie-in

`team-orchestration` gains one line: when a task needs the user, append a line to
`.claude/board/waiting.md` (`- <date> · <what> · <how to answer>`) and remove it when
answered. That is the only orchestrator-side change.

## Data flow

hooks (`Stop`/`SubagentStop`) → `board_refresh.py` → `board.py build` → `index.html` +
`board.json` → browser pane / Artifact. `/board` is the manual path for the same build.

## Error handling

- `gh` missing or unauthenticated, `bd` missing, no transcripts: the section shows
  "unavailable" with the reason; the page still builds.
- Malformed transcript lines are skipped; a session with no assistant messages shows title
  only.
- The hook never blocks a turn: any exception → exit 0.

## Testing

- `scripts/test_board.py`: fixtures for `gh pr list` JSON, `bd list --json` output, two
  session transcripts (one running with a subagent, one finished with an unanswered
  `AskUserQuestion`), and a `waiting.md`; assert each section's parsed model, the
  waiting-on-you merge, the running/done heuristics, secret redaction, and that build never
  raises when every source fails.
- `validate_assets.py` for the hook entry, `validate_skills.py` for the skill, catalog regen.
- Smoke: `/board` in this repo during a `/team` run; screenshot in the browser pane.

## Out of scope

Editing beads or PRs from the page; live updates (the hook refresh is enough); multi-repo
aggregation (one board per repo); the desktop app's own background-tasks pane (already shown
beneath the browser pane).
